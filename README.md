# Shop Game

ファンタジー世界の村のよろず屋から始め、仕入れ、倉庫整理、陳列、販売で資金を稼ぎながら、城下町やほかの地域へ店を広げていく店舗経営シミュレーションゲームです。

## MVPの設計メモ

村のチュートリアルで「店舗経営＋冒険者支援による攻略」を一通り体験する方針です。会話で決めた仕入れ・引き取り・一般客への販売・3人への支援・討伐・暦・日誌・次の街への同行判断と、未決定事項は [MVP仕様・相談記録](docs/MVP.md) にまとめています。このメモは実装完了を意味しません。

## 基本コンセプト

- 店舗経営と、商品の形や倉庫の空間を考える整理パズルを組み合わせます。
- スマートフォンでのプレイを優先し、PC ブラウザでも快適に遊べることを目指します。
- 時間制限やリアルタイム操作を基本とせず、自分のペースで進められる設計です。
- 静的な画面を中心にし、過剰なアニメーションや常時動くキャラクター表現は避けます。

## ゲームサイクル

メイン画面では「報告 → 仕入れ（ガチャ）→ 倉庫整理 → 陳列 → 支援 → 開店 → 営業 → 一日終了」の順に進みます。仕入れと支援にはスキップボタンがあります。準備中は前の工程へ戻れますが、取引中は入荷品すべての行き先を決めてから進みます。

メインとは別に「日誌・倉庫・住人・冒険者」のタブを使えます。別タブから戻ると進行中の工程を再開します。冒険者タブと支援工程で、パーティ編成・装備・支度金を共有します。目的地の選択と遠征の出発指示は、支援工程だけで行います。

村でのチュートリアルから出発結果までを実装したMVPです。次の街の本格的な経営は次段階です。目標達成後も出発までは村で経営を続けられます。

費用・確率・引取率・成功条件などは仮設定です。[実装後の確認事項](docs/MVP-確認事項.md) に判断が必要な点と現在の値をまとめています。

## 起動と最初の遊び方

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

[経営画面](http://localhost:8000/#home) を開きます。すでに同じポートのサーバーが動いている場合は起動し直す必要はありません。

- 報告を確認し、仕入れで商人と渡す金額を選びます。仮仕様として従来の費用・個数を1口とし、武器・防具商人は150 Gごとに4品、道具商人は120 Gごとに4品が入荷します。金額によって抽選率は変わりません。入荷品を収納または引き取りに振り分けて取引を終えます。
- 倉庫整理、陳列を終えたら支援へ進みます。冒険者タブでも事前に仲間を編成し、装備・支度金を渡せます。倉庫の装備候補を選んで装備枠をタップするか、候補の↕を枠へドラッグします。「支援を渡す」で装備の変更案を確定します。支度金は各パーティ枠のボタンから別に渡します。交換・取り外しした旧装備は使用済みとして倉庫へ戻り、価格は新品の50%になります。
- 支援工程で、地図の現在攻略可能な目的地を選んで遠征へ出発します。派遣条件は編成内の装備1人以上・参加者全員の療養終了です。最低支度金はなく、支度金は遠征で消費しません。危険率低下の効果は次段階で実装します。最大3パーティを編成できます。遠征は同時に1件です。
- 開店準備を確認して営業を始めると、来客の会話と購入結果を表示します。棚が空の日も販売なしで進められます。営業後は収支を確認して一日を終了し、翌日の報告で帰還・回復結果を確認します。
- 森（必要攻略値60）→野営地（140）の順に攻略します。翌日の帰還時に参加者の攻撃力合計だけ進み、必要値への到達でクリアします。参加者全員に実際の進度分の経験値が入り、遠征報酬はありません。野営地クリアで村が安全になります。怪我した仲間は1〜3日間療養します。資金不足では仕入れ工程の「村の手伝い」を使えます。
- 日誌には会話の全文を重ねず、商売・支援・遠征・収支を日付ごとの短いログで残します。住人タブは大工・教会の追加予定を表示し、増築・蘇生の操作はまだありません。
- 野営地クリアと3500 Gの所持金を達成すると、同行者を選んで出発できます。旅費に応じた開始資金を確認して確定してください。
- 「日誌」で支援・商売・討伐の記録を読めます。進行は自動保存され、「設定」からJSONの書き出し・読み込みもできます。

## 基本操作（プロトタイプ）

- 倉庫の商品をタップして選択し、選択中の商品をもう一度タップするか回転ボタンを押すと 90 度回転します。元の場所に収まらない場合は、近くの空き場所へ移動して回転します。
- 商品を選択して空きマスをタップすると、その場所へ配置します。
- 鉄の斧は、刃が横2マス、柄が縦に伸びるL字型のサンプルです。空白部分に魔晶石などの別商品を配置でき、90度ずつ4方向に回転できます。使用マス数は空白を除いて数えます。斧の価格は検証用の仮値です。
- 長押ししてドラッグすると移動先をプレビューします。配置できない場所で指を離すと元の場所へ戻ります。
- 確定した直前の配置は「直前の配置を取り消す」ボタンで戻せます。
- 「陳列」画面では、倉庫の商品一覧から品物を選び、店舗の 5 × 5 グリッドの空きマスへ配置します。陳列品は回転・移動でき、選択した商品を倉庫へ戻せます。配置可能な場所は緑、置けない場所は赤でプレビューします。
- 商品一覧はカードのグリッドで表示し、アイコン・商品名・価格・所持数を確認できます。同じ種類の商品はまとめて数えます。
- スマートフォンでは画面切り替えを基本とし、PC では複数パネルの同時表示を検討します。

保存失敗時は画面下部に表示します。JSONで保管できます。異なるスキン・版や不正な配置を含むセーブは拒否し、既存の読み込み失敗データを自動で上書きしません。ブラウザやポートが違うとIndexedDBの保存先も別です。

## コードの構成

開発ルールは [`AGENTS.md`](AGENTS.md)、将来の機能候補は [`店舗ゲーム追加アイデア.md`](../店舗ゲーム追加アイデア.md) を参照します。アイデア一覧には未実装・未確定の構想も含まれます。

| 場所 | 責務 |
| --- | --- |
| `js/state/gameState.js` | 独立した初期ゲームデータを生成。選択やドラッグの状態は含めない |
| `js/data/locales/` | 世界観に依存しない操作文言 |
| `js/data/skins/` | 業態ごとの商品定義・初期在庫・表示データ・辞書 |
| `js/application/createSession.js` | スキンの組み立て、表示キーと状態の互換性の検証 |
| `js/systems/` | 配置判定・回転・移動・在庫の受け渡し。DOM に依存しない |
| `js/application/game.js` | 確定操作の窓口、成功時の通知、倉庫の取り消し履歴 |
| `js/ui/` | 画面ごとの描画・入力・一時状態。翻訳文の DOM 反映も担当 |
| `js/main.js` | ゲーム状態の生成と使用する画面の登録 |

UI は `game.warehouse` / `game.stocking` の操作窓口へ確定操作を渡します。成功した操作の通知を `ui/app.js` が受け、登録済みの画面を更新します。画面同士は互いを呼び出しません。失敗した配置やドラッグのプレビューでは通知しません。保存処理もこの通知へ接続し、成功した確定操作ごとに自動保存します。

画面を外すには、`main.js` の対象画面の import と登録行を外します。未登録の画面とナビゲーションは非表示になり、残った画面で引き続き操作できます。各画面は `mount(root, game)` で登録し、`render()` と、イベント・タイマーを解除する `destroy()` を返します。

画面を非表示にすることと、ゲームのシステムやデータを削除することは別の作業です。たとえば陳列画面には倉庫在庫のデータが必要ですが、倉庫画面のコードには依存しません。システム自体を外す場合は `application/game.js` の対応する操作窓口と import も整理します。既存セーブの移行は、保存機能を実装する際に設計します。

## 世界観・スキンの差し替え

現在のファンタジーは `js/data/skins/fantasy/` に分離しています。共通システムは商品IDを識別子として扱い、武器などの名前で動作を分岐しません。ペットグッズ・釣具・ドラッグストアなどのカタログも、同じ倉庫・陳列の仕組みへ渡せます。

スキンは次のデータを持ちます。

| キー | 内容 |
| --- | --- |
| `id` / `contentVersion` | 世界観とカタログ版の識別子 |
| `itemDefinitions` | 商品ID、カテゴリ・素材のキー、寸法、任意の形状マスク、価格などの計算用データ |
| `initialState` | 倉庫・棚のサイズと初期在庫 |
| `presentation` | 商品IDごとの `glyph` または `imageUrl`。画像はスキン内のアセットを `new URL(..., import.meta.url).href` で指定可能 |
| `locales` | 商品名・店舗名・通貨・ブランドなど、世界観固有の辞書 |
| `theme` | 共通CSSが参照する色などのカスタムプロパティ |

新しいスキンを作る時は、対応するフォルダとデータを追加し、`main.js` のスキンの import を差し替えます。ランタイムのスキン切替画面や、他業態の完成したカタログはまだありません。ペットショップはテスト用の最小データで検証しています。

名称・アイコン・色だけを変える場合は、`presentation`・`locales`・`theme` を変更すれば、価格・形状・在庫・操作結果はそのままです。商品構成も変えたい場合は `itemDefinitions` と `initialState` を差し替えます。既存の商品IDは維持できますし、別業態で別の商品IDも使えます。

ゲーム状態には `skinId` と `contentVersion` を持たせ、別業態や異なる版の状態は明示的に拒否します。これは保存データを将来分離するための基盤で、セーブ・ロードは実装済みですが、世界観をまたいだ在庫の変換は未実装です。

今後の顧客・需要・仕入れも、種類や特性をデータとして渡す方針です。新しい業態で独自のゲームルールが必要になった場合には、その機能を追加します。文言や画像の変更だけで新しいルールまで実装されるわけではありません。

ブラウザ用の回帰テストは、リポジトリで `python3 -m http.server 8000 --bind 127.0.0.1` を起動し、[テスト画面](http://localhost:8000/tests/ui.html) を開きます。片方の画面だけの登録、登録解除と再登録、空白マスのヒット判定、不正配置、マウス・タッチ相当の Pointer Events によるドラッグ・キャンセルを自動確認します。テストは専用の初期状態を使い、ゲーム画面の状態は変更しません。合成イベントのためネイティブのポインターキャプチャのみ代替し、実機タッチの確認とは区別します。

### JSONによる職業と装備種別（2026-11-03）

職業の装備可能種別は [jobs.json](js/data/skins/fantasy/jobs.json)、種別の装備部位・必要な手の数・共通装備の扱いは [equipmentTypes.json](js/data/skins/fantasy/equipmentTypes.json) で管理します。表示名は日英のロケール辞書に置き、商品定義の `equipmentType` と人物の `jobId` を使って判定します。

- 戦士（ブラン）：片手斧・両手斧・両手剣・重装備。

### 職業特性の固定ボーナス（2026-11-03）

`jobs.json` に特性を追加しました。剣士はHP＋1、戦士は防御＋1を固定で加え、レベルアップごとの追加加算は行いません。基礎能力・成長値は保存データに保持し、表示・参照時に職業特性を加えた実効値を計算するため、既存セーブの数値を変更せず適用でき、再読み込みでも重複しません。

魔法使いは装備品の `attributes` を属性ごとに合計した後、持っている属性へそれぞれ＋1します。炎＋1が1個なら炎＋2、2個なら炎＋3。炎と水の装備を持つ場合は両属性に各＋1し、装備のない属性には加算しません。倉庫の品や本人の保管装備は数えません。

冒険者詳細に特性と実効能力、装備属性を表示します。通常商品の属性値はまだ割り当てておらず、ダンジョン進度・危険判定への接続は後続段階です。
