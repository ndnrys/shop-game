# Shop Game

現在のゲームはルートの `index.html` です。提供された透過PNGの装備画像を使う画面を土台とし、`main` ブランチで実装を進めます。別の試作ゲームや開発用コピーはありません。

## 起動

リポジトリ直下で次を実行し、ブラウザで `http://127.0.0.1:8052/` を開いてください。

```sh
python3 -m http.server 8052 --bind 127.0.0.1
```

JSONをHTTP経由で読み込むため、HTMLファイルを直接開く方法には対応していません。ビルドや外部パッケージは不要です。

## 構成

- `index.html`：ゲームの入口と共通の画面枠。
- `css/game.css`：レイアウト、操作表示、スキンのCSS変数。
- `js/main.js`：一日の流れ、画面描画、操作、JSON読み込み。
- `js/item-core.js`：寸法、配置、回転、近傍の空き位置検索。
- `js/equipment-core.js`：個体耐久、価格、破損、補充候補の純粋計算。
- `js/equipment-ui.js`：装備画面・受け渡し・派遣と翌朝帰還。
- `js/economy.js`：固定費精算・治療・自然回復・棚増設。
- `js/save-game.js`：自動保存、JSON入出力、バージョン移行と検証。
- `data/item-catalog.json`：210種のアイテム定義。
  - `description` は商品説明文（文字列または `null`）。未設定の価格・能力・効果は従来どおり仮定せず、商品詳細画面で確認する。
  - 店舗の商品カード右上の `i` で商品情報を確認できる。カード本体のタップは複数選択のまま。
- `data/game-settings.json`：倉庫・表示・開発中の仮数値。
- `data/economy.json`：章別の固定費・棚増設費と、Lvあたり治療単価の暫定値。
- `tests/game.test.mjs`：現行実装のデータ・画面遷移・倉庫操作の確認。
- `docs/`：仕様と設計記録。`docs/data/` の職業・章・ダンジョン定義は今後の接続用。仲間の表示定義は `data/characters.json`。

## 現在動く機能

朝の報告 → 仕入れ → 仕入れ結果・倉庫整理 → 陳列 → 支援 → 営業 → 翌朝。

- アイテム210種の読み込み、検索、種類・装備枠の絞り込み、詳細表示。
- 19カテゴリ・210種の装備をPNG付きで表示。旧素材・旧装飾品・複合属性の将来候補は廃止。
- 仕入れた品を収納・引き取り。同じ画面で倉庫整理。
- 商品をクリックして選択、選択中の商品を再クリックして回転。
- 0.1秒長押しでドラッグ。入荷品も倉庫へ直接ドラッグ可能。
- 重なり・枠外の場合は近くの空きへ補正。置けなければ通知なしで元の状態を維持。倉庫外へのドロップ・キャンセルも元の状態を維持。
- 商品を棚へ補充・倉庫へ返却し、顧客の所持金・購入傾向・棚効果で販売し、売れ残りを翌日へ持ち越す売買処理。
- 陳列画面の「棚・設備の配置」で8×8マスに2×2の棚を配置・選択・移動できる。位置は進行データに保存され、旧セーブの棚は未配置として移行する。棚は100ms長押しでドラッグ移動し、タップすると棚の商品管理画面に切り替わる。棚の商品総額を表示し、棚と倉庫の両方で商品カードを複数選択して一括返却・補充できる。
- 常設メニュー「記録」に日誌と図鑑の入口を集約。商品・セット装備・人物の図鑑。商品は初期在庫と仕入れ時に発見し、一般客への販売確定時に販売個数を加算。木剣＋木の盾を同時に棚へ置くとセット発見。手放しても保存データに記録を保持。
- 画面下部の「☰ メニュー」から展開する6項目のナビゲーション（初期状態は閉じる）、ページ切替、3種類のスキン、設定JSONの書き出し。

## これから実装する部分

正式価格・装備能力・報酬、破産・次の街への移動は未完成です。日誌は表示サンプルです。朝の売上と帰還時の耐久消耗・破損は実際の結果を表示します。既存画面のボタンや文言だけで実装済みと判断しないでください。

`game-settings.json` の `development` は簡易経済の仮数値です。正式なアイテム価格は `item-catalog.json` の `price: null` として未設定のまま保持しています。

固定費は朝の報告時に前日分を精算し、店舗管理費・仲間維持費・5日ごとの税を表示します。住人の大工から棚を増設すると陳列容量と管理費が増えます。有料治療は対象1人のLv×200Gで即時回復し、自然回復は無料です。負傷発生は遠征へ接続済み。治療対象は保存された負傷状態を参照します。成長は遠征へ接続済み。村から第1章への章進行は接続済みです。金額は `data/economy.json` の調整用仮値です。[仕様・暫定金額・接続状況](docs/固定費・治療費仕様.md) を参照してください。

支払不能時は未払い明細を保持して経営進行を止めます。破産の本処理は別途接続が必要です。広告治療も未接続です。旧セーブは追加の経済状態を補い、遡って徴収しません。追加状態と明細は自動保存・JSON入出力に対応しています。

ゲーム進行はブラウザのlocalStorage（`shop-game-save`）に自動保存します。設定画面から進行JSONを書き出し・読み込みできます。保存バージョンは2。現行の在庫・装備構造を持つversion 1 JSONの耐久未設定個体は、`used: true`なら5/10、それ以外は10/10、未鍛冶へ移行します。旧版独自のIndexedDB構造の自動変換・削除は行いません。現在のmainには従来保存機能がなかったため、異なる旧版セーブの実物との互換性は未検証です。

## 図鑑の接続範囲

定義は `data/encyclopedia.json`、記録更新は `js/encyclopedia-core.js`、表示は `js/encyclopedia-ui.js` に分離しています。セットは既存の安定した商品IDを参照し、定義の追加で増やせます。「木の剣」は現行データの「木剣」を使用しています。商品図鑑は新一覧の210種のみを対象とします。

図鑑も進行データに保存します。帰還時に装備の冒険使用本数・遠征使用回数を更新します。人物の初遭遇・セット使用実績との連動は保留しています。人物の正式な定義・遭遇処理は未接続のため、人物タブは0/0件です。表示サンプルを出会いとして記録しません。「最初から」で図鑑を含む進行を初期化します。再読み込みでは保存状態を復元します。過去実績の推測は行いません。

商品の画像は `assets/equipment/` の透過PNGを使用します。図鑑タブなどの共通文言はUI内の `encyclopediaText` にまとめています。人物図鑑の画像・紹介文は正式データの接続時に対応します。

## キャラクター設定

`data/characters.json` に合意済み27人の名前・初期職業・加入章・初期Lv・本人の能力・固有属性を保存しています。元の安定したIDを維持し、日本語名と職業名を追加しました。現在の村の表示はカイル・ガレス・ミラで、支援の人物ボタンから初期能力を確認できます。帰還報告と装備見出しもこの定義を参照します。初期能力は調整可能な合意済み暫定値です。村の編成・育成は接続済み。第1章への移動時に新規3人の加入を接続済み。キャラクター画像も表示します。

支度金の予定額と加算操作は、経営の支援工程の「編成」内でパーティ枠の上に表示します。仲間タブでは非表示です。支度金の独立タブはありません。

編成では現在の章で使用可能な仲間全員をページ切替で表示し、所属パーティ番号（未編成は−）を表示します。パーティ1〜3は独立した3人枠です。編成はドラッグのみ。未編成または現在のパーティの仲間を、一覧・パーティ枠から目的の枠へドラッグして配置します。パーティ枠からキャラ一覧へドラッグすると未編成に戻ります。他パーティ所属の仲間は、元のパーティで外してから配置します。枠外ドロップ・キャンセルでは変更しません。パーティ内・一覧内のキャラをクリック／タップすると装備画面が開きます。別パーティや遠征中の仲間も装備の確認は可能です。村は最初の3人が第1パーティに所属し、第2・3パーティは空です。支度金の予定額もパーティ別で、派遣時に所持金から引きます。遠征中のパーティは編成・装備変更をロックします。村から第1章への進行・同行者1人の選択は接続済みです。

キャラの装備画面は×で開く前のパーティ・一覧ページへ戻ります。前／次のボタンで、この章で使える仲間を順番に切り替えられます。本人のHP・攻撃・防御・固有属性と職業・Lvを表示。装備補正は未設定のため能力に加算しません。

## 装備耐久度MVP

- 初期在庫は10/10。仕入れた装備は最大耐久8/9/10/11/12を10/20/40/20/10%で抽選し、新品は最大値で入荷します。定義のIDと個体UIDは維持します。
- 編成のキャラをクリック／タップし、倉庫候補を選んで対応する装備枠をタップ、または0.1秒長押しして枠へドラッグすると装備します。武器・盾・頭・胴・装飾品の5部位。装備枠から倉庫候補欄へドラッグ、または「外す」で取り外せます。交換・取り外しでは耐久度を維持して倉庫へ戻し、入らなければ状態を変えません。
- 支援工程の「目的地」で選択パーティを派遣。翌朝に参加者の各装備を1消耗し、0になった装備は消滅します。攻略進度は下記のダンジョン攻略に接続。怪我判定は接続済み、報酬は未接続です。装備中の時間経過や着脱では消耗しません。
- 部位別「自動再装備」は初期OFF。ONなら破損した商品IDを記憶し、次の派遣時に倉庫から同じ商品の未鍛冶品を補充します。最大耐久の低い順、同値なら現在耐久の低い順。在庫がなければ空欄と補充待ちを維持します。
- 販売価格は新品価格×max(0.1,現在耐久/最大耐久)を切り捨て。正式価格がnullなら従来の開発用販売価格を使用。商人引取はこの販売価格に開発設定の引取比率（現在20/200）を掛けて切り捨てます。倉庫・入荷画面で価格と耐久度を表示します。
- `forged`・`forgeType`を個体に保持。鍛冶済みは自動補充・陳列・販売・商人引取を禁止し、手動装備・倉庫保管・破棄は可能。加工画面・効果・素材・費用は将来実装です。

`tests/durability-ui.html?width=390&height=844` は20画面の収まりと帰還処理を検証するブラウザ用ページです。育成追加後は360×640・390×844で確認。PC幅の再検証は省略。実機タッチは未確認です。

## 破産救済・村人からの寄付（2026-11-04）

朝の固定費が払えない場合、国から借入して支払いを継続します。在庫・仲間の装備は失いません。破産回数・累計借入・章別借入を保存。必要資金は基本額＋借入累計の120%、基本額の2倍で上限。上限後も借入可能です。1回の借入で固定費を賄えない場合は必要口数をまとめて提供し、口数分を記録します。

`data/game-settings.json` の `bankruptcy` で章ごとの基本必要資金3500G・借入1000G（調整用仮値）、倍率を設定します。朝の報告で必要資金・破産回数・累計借入と直近の救済内容を確認できます。派遣目標は進度100%。村の攻略・資金条件と章クリア結果画面を接続済みです。

仕入れ画面の「村人からの寄付」から本日の残り回数・前回報酬を確認。`donation` は広告1回3品・UTC 00:00更新・1日3回。広告SDKは未接続で通常プレイでは受取不可。連携先は `registerDonationAdapter({showRewardedAd})` に、正常完了時のみ `{completed:true}` を返す非同期処理を登録します。中断・失敗は報酬なし。同時要求は拒否します。

報酬は回数と一緒にセーブし、入荷待ちへ格納。満杯でも消失せず、既存の収納・引取で振り分けます。入荷待ちがある間は追加視聴不可。旧セーブでは新項目を初期化し、他の進行を維持します。端末のUTC時計を使います。ローカルJSONの手動改変・過去バックアップの復元への不正対策は広告サーバー連携の範囲です。

## 売買・棚効果（2026-11-04）

棚を選んで補充・返却し、営業後の「翌日へ」で章別の来店者数、顧客構成・所持金、購入傾向から売買を確定します。セットは同じ棚の必要個数を一括販売し、余剰は単品販売。セット＋30・同一商品＋20・同一部位＋10パーセントポイントの順で、商品ごとに1効果を適用します。販売後は残り在庫で再判定。朝の報告から前日の販売明細をページ切替で確認できます。

設定は `data/trading.json`。顧客・章・噂は開発用仮値、正式価格は未設定です。価格は従来の個体耐久による計算を維持し、噂や棚で値上げ・割引しません。噂の発動イベントは未接続で、発動関数・期間管理・客層補正・保存まで実装しています。[設定・暫定ルール・接続範囲](docs/売買・棚効果設定ガイド.md)を参照してください。

## 開発者用バランス調整

ローカルHTTPサーバーで [調整画面](http://127.0.0.1:8052/dev/balance.html) を開きます。数値編集後「変更を適用」で保存。初期値・現在値・変更状態を確認でき、デフォルト復元、調整JSONの書き出し・読み込みに対応します。空欄・範囲外・小数不可の項目・下限上限の矛盾・未定義キーは保存しません。JSON形式は `{"version":1,"overrides":{"game.development.initialGold":1500}}` です。インポートは全体を検証してから一括適用します。

ゲームは **`http://127.0.0.1:8052/index.html?dev=balance`** で起動します。同じオリジン（ホスト・ポート）の開発タブへstorageイベントで自動反映し、表示は次の操作で更新します。初期資金は新規ゲーム開始時、それ以外は次の関連計算（仕入れ・販売・帰還時の消耗・固定費精算・治療・借入など）から適用。所持金・在庫・仲間・確定済み明細は調整だけでは書き換えません。初期資金の確認で「最初から」を使うと既存進行はリセットされます。

調整値のキーは `shop-game-dev-balance-v1`、進行セーブとは別です。ただし開発プレイの結果は通常の進行セーブに保存されます。必要なら事前に進行JSONを書き出してください。通常URLでは調整値を無視し、localhost・127.0.0.1・::1以外では `?dev=balance` を付けても無効です。GitHub Pages等の本番ホストで開発設定は有効になりません。URLの秘匿はアクセス制限ではありません。

共有レジストリは `js/balance.js`。既存の `game-settings.json`・`economy.json`・`trading.json` をデフォルトの正本として参照し、追加した仕入れ個数・遠征消耗・価格下限・税周期は `runtimeDefaults` に集約しています。既存の数値ツリーに項目を追加すると同じカテゴリの数値が編集対象になります。保存構造に関わる倉庫寸法・棚容量・噂の期間・寄付上限は対象外です。耐久抽選は既存分布、商品抽選は一様のまま。開発画面の対象に成長・経験値・怪我・攻略・正式価格は含みません。遠征リスクは下記の設定JSONで調整します。

## ダンジョン攻略（追加仕様・第1項目）

支援工程の目的地ボタンから森・野営地を選択。帰還時に参加者全員の本人攻撃力の合計＋有利属性ボーナスを攻略進度へ一度だけ加算します。必要値で上限となりクリア表示、森クリアで野営地を解放します。出発時の能力を記録するため、遠征中の設定変更で帰還結果は変わりません。既存セーブの目的地なし遠征は耐久消耗のみ、新しい攻略進度は0から開始します。

正本は `data/game-settings.json` の `dungeons`。森60・野営地140・凶悪度3/5は旧設計値を採用した仮設定。推奨属性は森が火1・野営地が風1、ボーナス係数は各1の調整用仮値です。計算は推奨属性のキーに一致する全員の装備属性値合計×係数。推奨値は出発条件やボーナス上限ではありません。凶悪度は個別の怪我判定にも使用します。

装備の数値属性はカタログの任意項目 `attributes: {"fire": 2}` で定義できます。既存の `element` や名称から数値を推測しません。現行商品は属性値が未設定なので、現時点のボーナスは0。固有属性はこの装備属性合計には含めません。正式な攻撃補正も未設定を維持します。

## 冒険者パラメータ（追加仕様・第2項目）

## 冒険者の育成（追加仕様・第3項目）

冒険者をタップし、装備画面の「育成へ」から4つの育成方針を選択します。初期方針は均等。レベルアップごとに3ポイントを自動配分し、方針は仲間ごとに保存します。均等＝攻撃1・防御1・HP1、攻撃重視＝2・0・1、防御重視＝0・2・1、HP重視＝0・1・2。方針変更で過去の成長値は変わりません。遠征中の変更も、次のレベルアップ時から適用します。

経験値は帰還時に `floor(その遠征で実際に増えた攻略進度 / 出発時の参加人数)` を参加者全員へ付与します。120進んで3人なら各40、7進んで3人なら各2。最後の遠征は必要値までの実増加量を使い、攻略済みの目的地では経験値を得ません。切り捨てた端数は持ち越しません。遠征で死亡する参加者も分配人数に含め、経験値・成長を記録してから死亡状態を反映します。過去の遠征実績から経験値は推測しません。目的地なしの旧遠征にも付与しません。

必要経験値は `adventurers.growth.experience` の仮設定で、現在は45＋（現在Lv−1）×45。レベルアップ時に必要量を差し引き、余りは持ち越します。大量獲得で複数レベル上がる場合も同じ方針で成長します。育成済みの攻撃は次の遠征の攻略進度、防御・HPは次の怪我判定へ反映。治療費は現在Lvを使います。出発済み遠征の攻略力と怪我判定結果を遡って変更しません。

演出は枠なしの全画面オーバーレイで、背景だけを暗くします。画面高さ・セーフエリアに合わせて縮小し、低い横向き画面でも操作ボタンと商品カードを画面内に配置します。共通ダイアログのボタン余白を継承せず、画像は残り高さに追従します。`tools/purchase-demo.html` で購入なしに共通演出を確認できます。


## 仕入れの商人画像

仕入れの回数選択欄に武器商・防具商・道具商の右列の会話アイコンを表示します。＋で左列の喜ぶ表情、−で中央列の困る表情に切り替え、最後の操作から0.5秒後に右列へ戻ります。商人ごとに独立し、0回で−を押した場合も表情を切り替えます。確定後は選択した各商人を順に右から左へ0.9秒で出だしを速く、停止前に減速して移動し0.5秒停止させます。その後、`assets/shopkeeper/shopkeeper-surprised-hq.png` を左右反転して左から右へ0.9秒で出だしを速く、停止前に減速して移動し0.5秒停止させ、宝箱・結果表示へ進みます。スキップ可能で、画像の読み込み失敗時も処理を継続します。仕入れの抽選・料金・入荷数は変更していません。

`assets/merchants/merchant-icons.png` は `merchant-icons-transparent-fixed.png` から取り込んだ透過RGBAの1448×1086px（3列×3行）。列境界0・483・965・1448px、行境界0・362・724・1086pxで切り出し、カウンターの中央・下端を揃えた400×280pxの個別PNGにしています。表情による横ずれを防ぎ、表示枠は88×56px（狭い画面は80×56px）です。`merchant-portraits.png` は2172×724px（3列）で、立ち絵は724×724pxです。表示は縦横比を維持し、演出は画面の残り高さに合わせて縮小します。動きを減らす設定では商人のスライドを抑制します。


`tests/merchants-ui.html` で3商人の通常画像・選択商人の順次登場・停止位置の収まり・スキップ・画像失敗時の継続を確認できます。360×640・1280×800のChrome自動検証に通過。従来の `tests/effects-ui.html` も360×640で通過。実機タッチと実時間でのアニメーションの目視確認は未実施です。Nodeテストは75件中27件成功・48件失敗で、変更前のmainと失敗項目は一致（既存テスト環境の `GameEffects` 未定義など）。


仕入れ演出の最後の宝箱は `assets/effects/open_box.gif`（437×435px、8フレーム、各160ms）を使用します。繰り返しを止め、読み込み完了から1120msで完全に開いた最終フレームになり、800ms維持して1920msで仕入れ商品の確認へ進みます。毎回先頭から再生し、読み込み失敗時は商品確認へ進みます。読み込み待ちは最大4秒で、商品を見るボタンでも進めます。


営業中の購入客は `data/trading.json` の各顧客の `image` で住人PNGを指定します。村人・戦士・弓使い・魔法使い・僧侶・盗賊・旅人の7客層に接続し、画像失敗時は従来の絵文字へ戻ります。画像の対応は見た目で選定しており、売買判定・客層の重み・所持金は変更していません。


朝の営業報告・仲間の帰還報告は、店員の説明文と既存の明細を併記します。`shopkeeper-normal.png` と `shopkeeper-talking.png` を同じ枠に重ね、約4.8秒間口元を切り替えてから通常表情へ戻ります。音声はありません。動きを減らす設定では通常表情のみ表示します。金額・帰還結果・工程進行の処理は維持しています。

朝の報告は売上・来店と購入人数・固定費の内訳・支払い状況・帰還結果を店員の吹き出し内で説明します。クリア必要資金・破産回数・累計借入の常時表示は朝の報告から外し、計算と保存は維持します。当日の国からの資金提供は説明します。

購入者が0人の場合は購入なしと説明し、0Gの固定費内訳は省略します。店員と吹き出しは報告領域の縦中央に配置し、店員画像を拡大しています。

朝の報告は「売上・費用」「お客様の声」「パーティ報告」の3ページです。吹き出しを店員の上に全幅表示し、前後のボタンで切り替えます。お客様の声は営業中と同じ購入・見送りのメッセージを実際の件数でまとめます。固定費合計の下に内訳を表示し、追加徴収はしません。

「お客様の声」は販売明細の来店客を2人ずつ、住人画像・接客時のセリフ・購入商品と金額（または購入なし）で表示します。お客様の切替ボタンで全来店客を確認できます。吹き出しの「店員」見出しは省略しています。

朝の報告の店員画像は下段の固定領域に配置し、メッセージの長さやページ切替で縦位置・大きさが変わらないようにしています。

パーティ報告の後は店員（`shopkeeper-oh.png`）で「今日も一日がんばりましょう！」「仕入れにいってきまーす！」と表示します。続くボタンで仕入れへ進みます。報告は全4ページです。

## 道具屋UIの試作（codex/warm-shop-ui）

ユーザー指定の別ブランチで、画像案を既存ゲームに反映しています。標準スキンは生成り・焦げ茶・深緑。木目調ヘッダーと、常設の「お店・倉庫・仲間・記録・メニュー」を共通化しました。メニューから設定・住人・情報屋・開発用切替を開けます。経営の工程切替も維持します。

- 朝の報告：売上・人数・固定費の帳簿と、店内背景・店員。帰還した仲間は1人ずつページ切替。
- 仕入れ：3商人の立ち絵カード、数量、合計と確定ボタン。
- 倉庫：残り高さに合わせた8×8盤面、商品情報、既存の回転・ドラッグ操作。
- 陳列：棚4枠と倉庫候補4品ずつのページ切替、棚総額と補充・返却。
- 探索：イメージ地図・目的地の攻略進度・選択パーティ。編成と支援は別表示。
- 編成・装備：人物カード、装備5枠、倉庫候補の商品画像。
- 営業：店内と直近のお客様、実際の取引履歴を2件ずつページ切替。
- 図鑑：商品画像と未発見タイル、発見数と進捗。記録は従来どおり保存。
- 設定：表示・セーブ・設定データの3ページ。

人物・商品は既存画像、店内と地図は追加生成したWebPです。地図は雰囲気を示す共通背景で、章ごとの地形や実際のルートは表しません。経済設定・商品定義・初期在庫・保存形式は変更していません。画像案の人物イラスト・背景・配置の完全一致を保証するものではありません。

起動方法は従来どおりです。このチャットのプレビューは `http://127.0.0.1:8054/`。新しい検証ページは `tests/warm-ui.html`（空・在庫ありの画面収まり）と `tests/warm-operations.html`（マウス／タッチ相当の回転・ドラッグ・装備・取消）。詳細は[UIデザインガイド](docs/UIデザインガイド.md)を参照してください。
