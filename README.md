# Shop Game

現在のゲームはルートの `index.html` です。画像を使わない画面構成を開発の土台とし、`main` ブランチで実装を進めます。別の試作ゲームや開発用コピーはありません。

## 起動

リポジトリ直下で次を実行し、ブラウザで `http://127.0.0.1:8052/` を開いてください。

```sh
python3 -m http.server 8052 --bind 127.0.0.1
```

JSONをHTTP経由で読み込むため、HTMLファイルを直接開く方法には対応していません。ビルドや外部パッケージは不要です。

## 構成

- `index.html`：ゲームの入口と共通の画面枠。
- `css/game.css`：レイアウト、操作表示、スキンのCSS変数。
- `js/main.js`：一日の流れ、画面描画、操作、JSON読み込み。
- `js/item-core.js`：寸法、配置、回転、近傍の空き位置検索。
- `js/equipment-core.js`：個体耐久、価格、破損、補充候補の純粋計算。
- `js/equipment-ui.js`：装備画面・受け渡し・派遣と翌朝帰還。
- `js/save-game.js`：自動保存、JSON入出力、バージョン移行と検証。
- `data/item-catalog.json`：235種のアイテム定義。
- `data/game-settings.json`：倉庫・表示・開発中の仮数値。
- `tests/game.test.mjs`：現行実装のデータ・画面遷移・倉庫操作の確認。
- `docs/`：仕様と設計記録。`docs/data/` の職業・章・ダンジョン定義は今後の接続用。仲間の表示定義は `data/characters.json`。

## 現在動く機能

朝の報告 → 仕入れ → 仕入れ結果・倉庫整理 → 陳列 → 支援 → 営業 → 翌朝。

- アイテム235種の読み込み、検索、種類・装備枠の絞り込み、詳細表示。
- 複合属性2種を将来候補として通常入荷から除外。
- 仕入れた品を収納・引き取り。同じ画面で倉庫整理。
- 商品をクリックして選択、選択中の商品を再クリックして回転。
- 0.1秒長押しでドラッグ。入荷品も倉庫へ直接ドラッグ可能。
- 重なり・枠外の場合は近くの空きへ補正。置けなければ通知なしで元の状態を維持。倉庫外へのドロップ・キャンセルも元の状態を維持。
- 商品を棚へ補充・倉庫へ返却し、販売して翌日へ進む簡易経済処理。
- 常設メニュー「記録」に日誌と図鑑の入口を集約。商品・セット装備・人物の図鑑。商品は初期在庫と仕入れ時に発見し、一般客への販売確定時に販売個数を加算。木剣＋木の盾を同時に棚へ置くとセット発見。手放してもゲーム中は記録を保持。
- 常設6タブ、ページ切替、3種類のスキン、設定JSONの書き出し。

## これから実装する部分

正式価格・能力・成長・戦闘・報酬・攻略度の遠征計算、固定費・破産・次の街への移動は未完成です。日誌は表示サンプルです。朝の売上と帰還時の耐久消耗・破損は実際の結果を表示します。既存画面のボタンや文言だけで実装済みと判断しないでください。

`game-settings.json` の `development` は簡易経済の仮数値です。正式なアイテム価格は `item-catalog.json` の `price: null` として未設定のまま保持しています。

ゲーム進行はブラウザのlocalStorage（`shop-game-save`）に自動保存します。設定画面から進行JSONを書き出し・読み込みできます。保存バージョンは2。現行の在庫・装備構造を持つversion 1 JSONの耐久未設定個体は、`used: true`なら5/10、それ以外は10/10、未鍛冶へ移行します。旧版独自のIndexedDB構造の自動変換・削除は行いません。現在のmainには従来保存機能がなかったため、異なる旧版セーブの実物との互換性は未検証です。

## 図鑑の接続範囲

定義は `data/encyclopedia.json`、記録更新は `js/encyclopedia-core.js`、表示は `js/encyclopedia-ui.js` に分離しています。セットは既存の安定した商品IDを参照し、定義の追加で増やせます。「木の剣」は現行データの「木剣」を使用しています。商品図鑑は235種を対象とし、通常入荷しない将来候補2種も未発見として表示します。

図鑑も進行データに保存します。帰還時に装備の冒険使用本数・遠征使用回数を更新します。人物の初遭遇・セット使用実績との連動は保留しています。人物の正式な定義・遭遇処理は未接続のため、人物タブは0/0件です。表示サンプルを出会いとして記録しません。「最初から」で図鑑を含む進行を初期化します。再読み込みでは保存状態を復元します。過去実績の推測は行いません。

既存の画像アセットと翻訳辞書はありません。商品の既存形状表示を再利用し、図鑑タブなどの共通文言はUI内の `encyclopediaText` にまとめています。人物の画像・紹介文は正式データの接続時に対応します。

## キャラクター設定

`data/characters.json` に合意済み27人の名前・初期職業・加入章・初期Lv・本人の能力・固有属性を保存しています。元の安定したIDを維持し、日本語名と職業名を追加しました。現在の村の表示はカイル・ガレス・ミラで、支援の人物ボタンから初期能力を確認できます。帰還報告と装備見出しもこの定義を参照します。初期能力は調整可能な合意済み暫定値です。後続章の加入・実際の編成や育成・画像の表示は未接続です。

支度金の予定額と加算操作は、経営の支援工程の「編成」内でパーティ枠の上に表示します。冒険者タブでは非表示です。支度金の独立タブはありません。

編成では現在の章で使用可能な仲間全員をページ切替で表示し、所属パーティ番号（未編成は−）を表示します。パーティ1〜3は独立した3人枠です。編成はドラッグのみ。未編成または現在のパーティの仲間を、一覧・パーティ枠から目的の枠へドラッグして配置します。パーティ枠からキャラ一覧へドラッグすると未編成に戻ります。他パーティ所属の仲間は、元のパーティで外してから配置します。枠外ドロップ・キャンセルでは変更しません。パーティ内・一覧内のキャラをクリック／タップすると装備画面が開きます。別パーティや遠征中の仲間も装備の確認は可能です。村は最初の3人が第1パーティに所属し、第2・3パーティは空です。支度金の予定額もパーティ別で、派遣時に所持金から引きます。遠征中のパーティは編成・装備変更をロックします。後続章への進行・同行者選択は未実装です。

キャラの装備画面は×で開く前のパーティ・一覧ページへ戻ります。前／次のボタンで、この章で使える仲間を順番に切り替えられます。本人のHP・攻撃・防御・固有属性と職業・Lvを表示。装備補正は未設定のため能力に加算しません。

## 装備耐久度MVP

- 初期在庫は10/10。仕入れた装備は最大耐久8/9/10/11/12を10/20/40/20/10%で抽選し、新品は最大値で入荷します。定義のIDと個体UIDは維持します。
- 編成のキャラをクリック／タップし、装備画面の5部位の枠から部位を選ぶと、対応する倉庫在庫だけを表示します。在庫のクリック／タップで装備します。交換・取り外しでは耐久度を維持して倉庫へ戻します。倉庫に戻せない交換は状態を変えません。
- 支援工程の「目的地」で選択パーティを派遣。翌朝に参加者の各装備を1消耗し、0になった装備は消滅します。戦闘・報酬は未接続の確認用遠征です。装備中の時間経過や着脱では消耗しません。
- 部位別「自動再装備」は初期OFF。ONなら破損した商品IDを記憶し、次の派遣時に倉庫から同じ商品の未鍛冶品を補充します。最大耐久の低い順、同値なら現在耐久の低い順。在庫がなければ空欄と補充待ちを維持します。
- 販売価格は新品価格×max(0.1,現在耐久/最大耐久)を切り捨て。正式価格がnullなら従来の開発用販売価格を使用。商人引取はこの販売価格に開発設定の引取比率（現在20/200）を掛けて切り捨てます。倉庫・入荷画面で価格と耐久度を表示します。
- `forged`・`forgeType`を個体に保持。鍛冶済みは自動補充・陳列・販売・商人引取を禁止し、手動装備・倉庫保管・破棄は可能。加工画面・効果・素材・費用は将来実装です。

`tests/durability-ui.html?width=390&height=844` は12画面の収まりと帰還処理を検証するブラウザ用ページです。360×640・390×844・1280×900で確認。実機タッチは未確認です。
