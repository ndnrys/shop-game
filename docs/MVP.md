# MVP仕様・相談記録

最終更新：2026-11-02

この文書は、村のチュートリアルとその後の構想について、会話で合意した内容を残すための設計メモです。記載は実装済みを意味しません。現在の実装状況は [README](../README.md)、開発ルールは [AGENTS.md](../AGENTS.md)、広い将来構想は [店舗ゲーム追加アイデア.md](../../店舗ゲーム追加アイデア.md) を参照してください。

数値の例、提案段階の仕様、将来構想は、確定事項と区別します。未決定の値を実装者の判断だけで確定しないでください。

## ゲームの核

**店舗経営＋冒険者への支援による地域攻略**を遊ぶゲームにする。

- 商人として商品を仕入れ、倉庫を整理し、店頭へ陳列して利益を得る。
- 販売先には、支援している仲間とは別の、一般客として来店する外部の冒険者も含む。支援相手だけで商売を完結させない。
- 仲間の冒険者へ装備と支度金を提供し、討伐依頼を進める。
- 同じ商品を「売って利益にするか、仲間への支援に使うか」を選ぶ。
- 将来は討伐素材の持ち帰りと鍛冶屋での加工が加わり、販売・支援へ循環する。

## 村とチュートリアル

### 合意した方針

- 最初の舞台は村のよろず屋。店の経営そのものをチュートリアルにする。
- 導入専用の使い捨ての場所にはせず、チュートリアル後も村の店を続けて遊べる方針。
- チュートリアルで支援する冒険者は3人。同じ攻略地域へ3人全員で繰り返し遠征し、攻略率100%で出現するボスに挑む。
- 村の近くにいる小規模な魔物グループのリーダーを討伐する。
- クリア条件は「リーダー討伐による村の安全確保」と「目標所持金への到達」の両方。
- 目標金額の名目は、次の街で店を購入して開業するための資金。
- 仕入れ・整理・一般客への販売・支援・討伐を一通り体験させる。
- チュートリアルの討伐では属性や相性まで考えさせない。

### MVPの到達点の提案

村での経営からリーダー討伐、出発条件の達成、同行者の選択と次の街の開始資金の確認までを、一続きに遊べる状態を目指す。次の街の本格的な経営・攻略は次段階に回す案。

この到達点、およびクリア後に任意のタイミングで出発するか、討伐と貯金の達成順を自由にするかは、最終確認が必要。

## 仕入れ・収納・引き取り

### 合意した仕組み

- 仕入れはゲーム内資金を支払うガチャ形式。
- チュートリアルに武器商人・防具商人・道具商人が登場する。
- 商人の専門に応じて入荷商品の傾向が異なる。専門外の商品も入荷する。
- 入荷品のうち必要な商品を選んで倉庫へ入れ、不要な商品は格安で引き取ってもらえる。
- 引き取りには、今回の入荷品だけでなく、以前から倉庫に保管している商品も渡せる。
- 引き取り先は、**そのとき仕入れている相手だけ**。引き取りだけの利用は設けないという会話上の整理。
- 専門に合う商品は、専門外の商品より少し高く引き取る。
- 今すぐ安く渡して倉庫を空けるか、倉庫を圧迫してでも後日の別商人との仕入れ時まで保管するかを選べる。
- 店頭販売や支援に使うために商品を残す選択もある。

### 例示された数値（未確定）

- 武器商人の仕入れ：武器70%、それ以外30%。
- 防具商人の引き取り：基準価格100の武器なら10、防具なら15。

これらはバランスの例であり、正式な確率・引取率ではない。引取額の基準を通常販売価格にするか、端数をどう扱うかも未決定。

### 提案・未決定

- 抽選後の商品を倉庫へ収納するまで置く、一時的な「入荷置き場」を用意する案。
- 支払い・抽選・収納・引き取りの確定タイミング、取引中断時や倉庫満杯時の扱い。
- 仕入れ1回の費用・入荷数・商品候補・抽選率・商人の利用条件。
- 資金を使い切った場合など、経営が詰まったときの立て直し手段。

## 一般客への販売

- 外部の冒険者などの一般客へ陳列商品を売り、経営収入を得る。MVPの必須要素。
- 仲間への支援は、一般客への販売とは別の操作・仕組みとして扱う。
- 一般客は購入の有無にかかわらず来店時に一言話す。経営画面と日誌に残し、将来は情勢や噂を載せてプレイヤーの判断材料にする。現在のMVPでは会話のみで、需要変化や情報の有効期限は未実装。
- 客の来店数、予算・好み、購入判定、販売価格、営業を進める操作は未決定。
- 仕入れ抽選から顧客購入を実行せず、仕入れと販売の責務を分ける。

## 冒険者への支援と討伐

### 合意した仕組み

- 装備の支援に加えて、支度金も渡す。
- 装備は部位別に渡せる。2026-11-02の追加合意により、交換・取り外しした装備は使用済みとして倉庫へ戻す。価格は新品の50%。
- 遠征の成果の確率は「冒険者の能力」「装備性能」「支度金の額」で増減する。
- 一度の成否で攻略終了にはしない。遠征を繰り返して攻略率を上げ、100%でボスが出現する。ボスに勝つと村が安全になる。
- 冒険者は遠征で経験値を得て成長する。怪我で療養が必要になる場合があり、回復に必要な日数が過ぎるまでは派遣できない。
- チュートリアルの分量は約1年半（30日）を目安に、経営と攻略の両方を調整する。100回程度の通しプレイで調整するよう指定され、結果は [30日調整記録](MVP-30日調整.md) に記録した。
- チュートリアルは3人で1つの依頼に出発し、属性や相性は扱わない。
- 攻略場所の難易度に応じて遠征日数が増減する。最低1日。
- チュートリアルの依頼は翌日に帰還する。

### 提案・未決定

- 派遣前に成功確率と帰還予定日を表示する案。
- 3人の能力をどう集計するか、支度金を個人単位・依頼単位のどちらで渡すか。
- 数値の調整結果は [30日調整記録](MVP-30日調整.md) を参照。装備更新後の旧装備の再利用方法など、未実装の細部は今後検討する。
- 遠征中の経営と翌日への進行手順、帰還処理の時点。
- 成功と日数短縮は別に扱う方針。支度金で日数まで変わるとは決めていない。

## 暦と日誌

- 1季節は5日。春夏秋冬で1年20日として整理する。
- 年・季節・日が分かる簡単な日誌を設ける。
- 誰にいくら支援したか、その日の店の売上などを記録する。
- ファンタジースキンでは、羊皮紙に書かれたような静かな見た目にする。

表示例（名前・金額は仮）：

> 1年目 春1日  
> リナに装備と支度金100を渡した。  
> 店の売上は240だった。

仕入れ費用・引取額、支援装備、討伐への出発・帰還・結果、地域解放や出発の節目も自動で残す案。記録対象の詳細と日付の更新手順は未決定。

日誌データは表示文そのものではなく、日付・出来事の種類・人物ID・商品ID・金額などの構造化した記録として保持する方針案。表示時に翻訳し、スキンに応じて羊皮紙から帳簿・業務日報などへ変更できるようにする。

## 次の街への移動と同行者

### 合意した狙い

- 新しい土地での開始資金を、前の土地で貯めた額にかかわらず、基本的に共通の基準へ揃えたい。
- そのうえで、育てた冒険者を連れていくかどうかによって開始条件に差を付ける。
- 同行者を連れていくと旅費が増え、開業資金は少し減る。その代わり育った冒険者により序盤の討伐依頼を進めやすい。
- 同行者を連れていかなければ旅費が少なく、そのぶん開始資金を多く使える。
- 新しい土地では、その土地の属性に合った人材が新たに紹介される。同伴者なしでも進められ、同伴者ありでも現地人材を得る意味がある。

説明用の例：所持金2000なら店代1900、所持金3000なら店代2900として、店の購入後に同額を残す。これは仕組みの説明であり、正式な店舗価格の決定式ではない。

「共通の基準額−同行者の旅費」を開始資金とする整理案。店舗・移転費用を含む「開業精算」として説明し、確定前に開始資金を表示する案も出ている。基準額・旅費・精算の名目や計算式・同行枠・引き継ぐ装備や在庫の範囲は未決定。

## チュートリアル後の発展（MVPで全面実装しない）

### 自由編成・同時依頼・待機

- 次の街以降では冒険者の人数を増やし、複数の依頼へ同時に派遣できるようにしたい。
- 固定パーティーにせず、依頼ごとにメンバーを選べる方針。
- 例：6人いる場合、依頼Aへ1人、依頼Bへ2人、依頼Cへ3人を同時に派遣する。
- あえて待機させる選択も重要。冒険者Aが遠征中でも、Cを別依頼へ出さず、Aの帰還後にA＋Cで次の依頼へ挑む判断ができるようにする。
- 人数を集中して成功を狙うか、分散して報酬機会を増やすかを選ぶ。
- 遠征ごとに参加者と帰還予定を持ち、同じ人を複数の遠征へ重複派遣しない方針。これはMVPでも将来を妨げないデータ設計にするための注意であり、自由編成・同時遠征を今すぐ全面実装する指示ではない。

### 討伐素材と鍛冶屋

- 討伐した冒険者が魔物の素材を持ち帰る仕組みを将来入れる。
- 素材は将来登場する鍛冶屋などで使えるようにする。
- チュートリアルでは素材獲得・加工は不要。報酬に素材を追加できる余地を残す。
- 素材の種類・数量・加工レシピ、通常商品と同じ倉庫枠で扱うかなどの詳細は、その機能を追加する時に決める。

### 広告による日数短縮

- 将来の特典として、広告視聴で遠征日数を1日短縮する案がある。
- チュートリアルで広告は実装しない。
- 帰還予定日を後から変更できる設計を考慮するが、広告サービスへの接続は別機能にする。
- 最短でも派遣翌日の帰還とする案が出ている。短縮の下限・回数・適用時点は未決定。

## MVP実装の推奨順（提案）

1. 仕入れ条件・引取額・一般客の購入判定・1日の進行と、資金不足からの立て直しを決める。
2. 仕入れ → 入荷品選択 → 倉庫整理・引き取り → 陳列 → 一般客への販売 → 収支確認、という小さな経営サイクルをつなぐ。
3. 暦・翌日への進行・日誌・セーブ／ロードを接続する。
4. 3人への装備・支度金の支援、1日遠征、リーダー討伐をつなぐ。
5. 討伐と目標所持金の両条件、同行者選択、開始資金の確認までをつなぎ、チュートリアルの案内を整える。
6. 最初から最後まで通しで遊び、支援する余裕・倉庫の選択・再挑戦・再開が成立するか確認する。

季節の需要効果、本格的な相性・育成・死亡／蘇生、従業員・複数店舗、鍛冶、同時遠征、広告、次の街の全面実装は、このMVPを完成させた後の追加候補。1季節5日の暦を採用することと、季節需要を実装することは分けて考える。

## 一日のルーチンと画面構成（2026-11-02 合意）

- メインは報告→仕入れ（ガチャ）→倉庫整理→陳列→支援→開店→営業→一日終了で進行。仕入れ・支援にスキップを置く。
- 別タブは日誌・倉庫・住人・冒険者。日誌はこれまでの流れを端的にまとめるログ、倉庫は現在の配置。
- 冒険者タブと支援工程でパーティ編成・装備・支度金を共通化する。地図での目的地選択と遠征出発は支援工程だけで行う。
- 住人は大工（マス目の増築）、教会（死亡した冒険者の蘇生）などを後から追加する。個別のルール・数値は未決定。
- ガチャは、どの商人にいくら渡すかによって入荷数が変わる。換算・抽選率の詳細は `MVP-確認事項.md` を参照。


## 部位選択と旧装備の再利用（2026-11-02 追加合意）

渡す装備は部位ごとのチェックボックスで変更を有効にし、右側のプルダウンで選ぶ。旧装備は倉庫へ戻し、使用済みの属性を付ける。ユーザー指定で販売価格は新品の50%、商人の引取額も値下げ後の価格を基準にする。

## 冒険者・ダンジョン改修（2026-11-03）

実装順と完了状況は [冒険者・ダンジョン実装チェックリスト](冒険者・ダンジョン実装チェックリスト.md) で管理する。

追加仕様として合意。以下は全体の実装完了を意味しない。

- ダンジョンは独立した攻略先。遠征参加者の合計攻撃力で進度を加算し、必要攻略値への到達でクリアする。別のボス戦は設けない。
- ダンジョンごとに凶悪度を持つ。遠征ごとに冒険者個人の負傷・死亡を判定し、防御・HPでリスクを軽減する。HPは減少する現在体力ではなく能力値で、1ポイントは1。療養期間にも影響する。具体式は未決定。
- 死亡後も装備は保持し、蘇生可能にする。蘇生条件は未決定。
- 職業・職業特性・装備制限は今後調整。装備は剣系・軽装備系などの分類を持つ。
- 武器・盾・胴防具・装飾品の4部位を維持。装備操作はドラッグ＆ドロップとタップ選択→装備枠タップへ変更する予定。
- 装備の元素属性値をパーティで合算し、攻略先の有利属性に応じて進度だけにボーナスを与える。推奨値を表示するが不足でも遠征可能。「炎＋1で進度＋10%」は設定例。具体値・上限・端数処理は未決定。
- 村は怪我による離脱を含め約30日を目安に調整する。

### 第1段階：個人の能力と成長選択

- キャラ定義に初期Lv・HP・攻撃力・防御力を持たせる。既存3人は初期Lv1、3能力は各3。
- レベルアップごとに本人の未選択成長回数を1増やす。育成方針を保存して自動成長させる方式は採用しない。
- 各レベルアップにつきボタンを1つ選ぶ。「平均」は各能力＋1。「攻撃重視」「防御重視」「HP重視」は対象＋2、残り2能力のどちらかへランダムに＋1。
- 未選択回数・選択後の能力・乱数状態を保存する。取引中・遠征中・出発後は選択できない。
- この段階では従来の能力値・装備性能による攻略計算と成長を維持し、新3能力の攻略・危険判定への接続は次段階とする。


### 第6項目：装備操作の変更

4部位の装備枠と倉庫候補を使い、ドラッグ＆ドロップ、またはタップ選択→装備枠タップで変更案を作る。ドラッグは候補の↕ハンドルから開始し、画面端では自動スクロールする。装備枠の「外す」で取り外しを準備し、取り消し操作で装備の変更案を破棄できる。

装備案はUI内に保持し、「支援を渡す」で支度金とまとめて既存の操作窓口へ渡す。返却失敗時は確定状態を変更しない。未確定の装備案は保存しない。職業制限は未実装で、現段階は部位の適合を判定する。


### 支度金のボタン入力（2026-11-03）

追加の支度金は＋10・＋100・＋1000のボタンで、押した回数分だけ加算する。追加予定額を表示し、「支援を渡す」で装備案とまとめて確定する。所持金を超える加算はできず、「クリア」で追加予定額を0へ戻せる。金額は人物ごとのUI一時状態で、確定成功後に0へ戻し、確定失敗時は保持する。


### 最大3パーティとパーティ別支度金（2026-11-03 追加合意）

- 最初は1パーティ。「＋」で空のパーティ枠を追加し、最大3組まで作成する。各パーティは既存編成に合わせて3人枠。
- キャラはドラッグ、またはタップ選択→枠タップで編成する。同一パーティ内では入れ替え、他パーティへの移動では元の枠から除く。移動先にいたキャラは待機へ戻し、重複所属は認めない。
- 編成・追加・取り外しは確定操作として保存する。キャラの選択とドラッグ中のプレビューは保存しない。
- 支度金を個人別からパーティ別へ変更する。各パーティの＋10・＋100・＋1000で追加予定額を作り、専用ボタンで確定する。装備の確定とは別操作にする。
- 編成変更やメンバー移動では支度金を移さない。支援工程で遠征パーティを選び、そのパーティの資金だけを消費する。
- 同時遠征は従来の1件を維持する。複数の同時遠征やパーティ削除は今回追加しない。
- 保存形式7へ更新し、旧個人支度金の残額はパーティ1へ合算する。旧遠征の乱数・参加者・支出済み金額は維持する。


### 職業・装備種別（2026-11-03 追加合意）

職業はJSONで管理する。剣士は片手剣・両手剣・重装備・軽装備、戦士は片手斧・両手斧・両手剣・重装備、魔法使いは杖・軽装備・布装備を使用できる。リナを剣士、ブランを戦士、ノアを魔法使いに設定する。盾・装飾品は全職共通とし、両手武器と盾の同時装備は禁止する。

既存の鉄・鋼の剣は片手剣、鉄の斧は片手斧、鎖かたびらは重装備、革の鎧は軽装備に分類する。商品には安定した装備種別キーを持たせ、表示名や商品IDの文字列を解析して判定しない。職業定義は `jobs.json`、種別定義は `equipmentTypes.json`、表示名はロケール辞書で管理する。

今回、職業固有の能力補正や新しい商品は追加しない。杖の片手／両手は商品ごとに明示する。盾がある場合は取り外しの変更を準備してから両手武器を選び、確定後の装備全体で排他条件を検証する。
