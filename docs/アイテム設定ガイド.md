# アイテム設定

`index.html` をHTTPプレビューで開いてください。ファイル構成を保ったまま利用します。

- `data/item-catalog.json`：アイテム235種、装備枠、装備種類、寸法、属性、鍛冶素材の用途。
- `data/game-settings.json`：倉庫サイズ、一覧の表示数、現在のゲームの確認用数値。
- `js/item-core.js`：配置・回転・重なり・枠外の判定。
- `js/main.js`：JSON読み込みと画面接続。

JSONを編集してブラウザを再読み込みすると反映されます。設定画面から現在読み込んだJSONを書き出すこともできます。ブラウザの操作から元ファイルへの上書きはしません。進行状況はまだ保存しません。

## 主なフィールド

`types` は種類ごとの設定です。`width` と `height` が配置に使う寸法です。`shapeLabel` は指定された形状の表記、`footprint` は配置形状で、今回の装備はすべて長方形です。種類を共通参照するため、寸法を1か所変更すると同じ種類の全アイテムに反映されます。

`items` は個別のアイテム設定です。`id` は名前を変更しても維持してください。`typeId` が種類への参照です。`element` は `none / fire / water / wind / earth / composite`、`status` は `active / planned`。`planned` は通常入荷から除外します。

未指定の `price`・`stats`・`durability` は `null` です。`price` を設定すると詳細画面に表示できます。能力・耐久はデータの保存先のみ用意しており、効果計算は今後の仕様に合わせて接続します。特殊装飾品も名前だけから能力を推定しません。

鍛冶素材の `effect` は属性付与の用途を記録しています。付与の実行、費用、量、対象、素材消費は未実装です。素材の寸法も未指定なので、倉庫への入荷対象にはしていません。

## 確認用の動作

倉庫ではアイテム選択後、空きマスを押して移動します。「回転」で90度回転。指定位置で収まらない場合、近い空き位置へ調整します。回転時は元の中心に近い位置を優先。同距離なら上・左を優先します。置ける場所がない場合はアラートを出さず、元位置・向きを保ちます。同じ商品を複数持てるよう、種類のIDと個別在庫のUIDを分けています。

仕入れ→収納→陳列→販売の接続は動作確認用です。商人プール内の一様抽選、費用、引取額、販売額は正式なバランスではありません。JSONの `development` に分けて保存しています。倉庫に入らない品は取引の入荷置き場に残ります。

ゲームの入口はルートの `index.html` です。この構成をメインのゲームとして開発します。

仕入れ結果と倉庫整理は同一画面です。上部で1品ずつ収納・引き取りを選び、その下の倉庫で移動・回転できます。入荷品が残っている間は陳列へ進めません。

倉庫操作：未選択の商品をクリック／タップで選択、選択中の商品を再クリック／タップで回転。100ms長押しでドラッグ開始。入荷品の商品名も長押しして倉庫へ直接収納できます。ドラッグ中は置き場所を強調表示し、倉庫外で離す・Escape・操作中断は元の状態を維持します。マウスとタッチはPointer Eventsで共通処理しています（実機タッチは未確認）。
