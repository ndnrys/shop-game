# ゲームデータの管理項目

更新日：2026-11-03

アイテム・ダンジョン・職業・キャラクターの基本定義をJSONに揃えるための仕様記録。後続のゲーム内整合性確認に使用する。現時点では項目の合意を保存する段階であり、既存データの移行や新しいゲーム効果の実装は行っていない。

## 共通方針

- 基本定義はJSON、計算処理はJavaScript、プレイ中の状態はセーブデータへ分離する。
- 表示名・説明は翻訳キーから参照する。
- アイテム、ダンジョン、職業、キャラクターの順に、一つずつ管理項目を整理する。

## 1. アイテム：合意した管理内容

| 項目案 | 内容 |
| --- | --- |
| `id` | アイテム固有の安定した識別ID |
| `nameKey` | 名前の翻訳キー |
| `descriptionKey` | 説明の翻訳キー |
| `category` | 商品カテゴリ。武器・防具・素材・装飾品の4種類 |
| `rarity` | レアリティを数字で管理 |
| `price` | 販売価格 |
| `shape` | 使用マスの配列。幅・高さを導出し、別のsize項目と重複管理しない |
| `seriesId` | シリーズの識別ID。シリーズ所属なしも可能 |
| `equipmentType` | 武器種と片手・両手を含む装備分類 |
| `bonuses` | HP・攻撃・防御の補正と元素属性値をまとめる項目 |
| `unlockChapter` | 入荷候補へ加わる章。数字で管理 |
| `image` | 画像の参照・切り出し情報 |

素材の種類を表す `material` は廃止する。元素属性（炎・水など）を管理する。商品カテゴリとしての「素材」は残す。

装備分類は「片手」「両手」だけではなく、片手剣・両手剣・片手斧・両手斧のように武器種まで含める。これにより既存の職業ごとの武器制限を維持できる。

現時点の分類案：片手剣、両手剣、片手斧、両手斧、杖、弓、矢、重装備、軽装備、服、盾、装飾品。装備部位・両手扱いは分類側で定義し、アイテム側へ重複して記述しない。新しい分類の職業別許可や弓・矢の組み合わせルールは別途整理する。

能力補正と属性値をまとめる構造の例（具体的な数値は未確定）：

```json
{
  "bonuses": {
    "hp": 0,
    "attack": 2,
    "defense": 0,
    "attributes": {
      "fire": 1
    }
  }
}
```

形状の例（縦3マス）：

```json
{
  "shape": [[1], [1], [1]]
}
```

### 追加時に整合性を確認すること

- シリーズは、棚に同じシリーズを置いた際の合わせ買いに利用する意図を保存する。購入条件・数量・確率・価格補正は未決定であり、ID追加だけで購入処理を変更しない。
- 章番号の開始値・進行方法と、既存の入荷解放日からの移行方法は未決定。
- レアリティの数値範囲・高低の意味・既存の文字列からの対応は未決定。
- 既存の薬・食料カテゴリの商品を4カテゴリのどこへ移すかは未決定。削除や独断の再分類はしない。
- 能力補正・属性値の具体値、属性の一覧、シリーズの一覧、各項目の必須／任意・省略時の扱いは移行前に整理する。
- 倉庫の個別在庫、所持数、使用済み、仕入原価、配置場所、装備者は基本定義ではなくセーブ側に置く。

## 2. ダンジョン：合意した管理内容

現行JSONは `js/data/skins/fantasy/dungeons.json`。以下は整理後の仕様であり、新項目・属性ボーナスのゲーム実装は未実施。

| 項目案 | 内容 |
| --- | --- |
| `id` | ダンジョン固有の識別ID |
| `nameKey` | 名前の翻訳キー |
| `descriptionKey` | 説明の翻訳キー |
| `chapter` | 所属する章。数字で管理 |
| `image` | ダンジョン画像 |
| `requiredProgress` | 必要攻略値 |
| `requires` | 解放に必要なダンジョンID |
| `duration` | 遠征日数 |
| `danger` | 凶悪度 |
| `fundingBase` | 支度金の軽減効果を決める基準額 |
| `map` | 地図上の位置 |
| `recommendedAttributes` | 属性ごとの推奨値。複数の属性を設定可能 |
| `attributeBonus` | 有効属性値1あたりの経験値増加率（％の数値。3なら3%） |

推奨値に登録された属性を有利属性として扱い、別の有利属性リストは持たせない。推奨値に満たなくても遠征可能。

### 属性による経験値ボーナス

- 実際の遠征参加者の属性値を属性ごとに合算する。
- 各属性の有効値は `min(パーティの属性合計, ダンジョンの推奨値)`。
- ダンジョンに登録されていない属性はボーナス対象外。
- 有効値の合計に `attributeBonus` を掛けた％だけ経験値を増やす。
- 最終経験値は増加分を加えた後に切り捨てる。`floor(基本経験値 × (100 + 有効値合計 × attributeBonus) / 100)`。
- 各参加者へ同じ最終経験値を付与する。基本経験値は従来どおり実際に増加した攻略進度。
- 以前の攻略進度ボーナス案を変更し、この属性ボーナスは経験値だけに適用する。攻略進度自体は増やさない。

設定例（具体的な各ダンジョンへの配分は未決定）：

```json
{
  "recommendedAttributes": { "fire": 3, "wind": 2 },
  "attributeBonus": 3
}
```

参加者の属性合計が炎2・風3・水2の場合、有効値は炎2・風2・水0の合計4。経験値ボーナスは12%。基本経験値100なら112、基本経験値9なら10（10.08を切り捨て）。

## 3. 職業：定義案をJSONへ保存

定義は [data/jobs.json](data/jobs.json)、日本語の職業名は [data/jobs.ja.json](data/jobs.ja.json)。項目・未決定事項は [data/README.md](data/README.md) を参照。

基本職「戦士・冒険者・魔法使い」から各2種、さらに各2種へ分岐する21職。同じ職業のキャラクターは共通の転職先を持つ。装備制限は基本職ごとに共通とし、転職では名称と固定ボーナスが変わる。属性ボーナスは職業由来で最大＋3。「精霊射手」は「魔弓士」に変更済み。

転職Lv・説明・画像は未決定としてnullで保持。ゲーム内の既存jobs.jsonやセーブはまだ変更しない。

## 4. キャラクター：初期設定と能力配分案

キャラクター定義は初めて出現・加入する際の設定に限定する。`initialStats` にHP・攻撃・防御と、炎1などの固有属性 `attributes` を含める。出現後の状態はセーブへ保存し、定義更新で上書きしない。

新しい村の3人はカイル（男）・ガレス（男）・ミラ（女）。各通常章で新規3人が加入し、終章の加入者は中央・東北・西南の団長3人（最上位職）。直前の章からの同行上限は1→2→3→4→5→6→6→6人として、最後は9人・3パーティ。

全27人の初期能力は [キャラクター初期能力案](キャラクター初期能力案.md)、未接続JSONは [data/characters.json](data/characters.json)。能力の具体値・加入Lvは後で調整可能な暫定値として合意済み。ゲームへの接続は未実施。

## 5. 章管理：定義案をJSONへ保存

世界観、三地方の戦い、団長、章ごとの加入・同行人数を [世界観・章構成メモ](世界観・章構成メモ.md) に記録。章の管理項目と引き継ぎルールを次に整理する。

章ごとの魔王軍の討伐対象を追加し、名前・画像を管理する。その対象の撃破が章クリア条件。構造案：`enemy: { nameKey, imageKey }`。対象とダンジョンの対応は次に整理する。具体的な敵や追加戦闘は未実装。

章データは [data/chapters.json](data/chapters.json)、表示名は [data/chapters.ja.json](data/chapters.ja.json) に保存。9章の接続・地方・魔王軍の討伐対象・章クリア条件・同行人数を定義した。敵の名前と章副題は仮案、画像・加入タイミング・村以降の攻略先・金銭等の引き継ぎは未設定。ゲームへの接続は未実施。

敵将・魔王は能力値不要。ダンジョンと同じく攻略進度を蓄積し、必要攻略値到達（表示100%）で撃破・章クリア。追加ボス戦は設けない。地方名は中央エルディア・東北ノルヴァン・西南サルディナを章の辞書に設定。
