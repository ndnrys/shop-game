# 倉庫拡張設定ガイド

新規ゲームの寸法は `data/game-settings.json` の `warehouse`（現在5×5）。拡張順は `warehouseExpansion.sizes: [5,6,7,8]`、次段階の費用は `costs: [300,600,900]`。費用は非負整数の調整用仮値。旧セーブの寸法は `legacySize: 8`。拡張時だけ費用を払い、既存の固定費計算に倉庫代は追加しない。

進行中の寸法は `warehouseSize: {width,height}`。配置判定・回転・ドラッグ・装備交換で倉庫へ戻す処理・図示・残容量は全てこの状態を参照する。設定の初期寸法を直接書き換えてプレイ中の拡張を表現しない。セーブ検証は保存された寸法で重なり・枠外を判定する。

倉庫サイズ未保存のversion 1/2 JSONは8×8へ移行する。過去データを縮小・自動再配置しない。未知サイズ・長方形・保存寸法に収まらない商品は読み込みを拒否し、読み込み前のゲームは維持する。費用を遡って徴収しない。

仕入れ・寄付・新規初期在庫は、現在の倉庫寸法へ回転込みで収まる種類に限定する。判定は `ItemCore.fitsBoard` を共用し、空き面積や配置済み商品は参照しない。槍1×7は5×5・6×6で対象外、7×7以降で対象になる。新規5×5は槍を除く5品で開始し、除外品の図鑑発見も付与しない。代替品・補償金・商品寸法は追加しない。既存セーブの大型品や入荷待ちは維持する。サイズ上は入る初期品が空き不足で配置できない場合は、従来どおり入荷待ちに残す。全入荷品を振り分けるまで進行しない。

住人は「教会 · 治療」「大工 · 拡張」の切替で縦スクロールを避ける。大工では倉庫・棚の拡張を選べる。仕入れ画面は倉庫寸法・空き面積を表示する。空き面積は収納可能個数の保証ではない。

検証：`node --test tests/game.test.mjs`。従来の8×8操作回帰用フィクスチャを残し、実設定の新規5×5・初期品保持・入荷制約・全拡張・保存復元・旧データ・資金不足・マウスとタッチ相当の移動・回転補正・取消を追加検証する。ブラウザ用は `tests/warehouse-ui.html?width=360&height=640` と390×844。合成Pointer Eventsではキャプチャだけを模擬し、実際のDOM矩形でドロップを判定する。PC画面・実機タッチは未確認。

倉庫費用・初期収納待ちが経済判断へ与える影響を含む約30日の通しプレイは未検証。遠征育成シミュレーションの28〜31日は倉庫拡張費・商品処分を含まない。
