# 冒険者の育成設定

第3項目を現行mainに接続済み。設定正本は `data/game-settings.json` の `adventurers.growth`、本人の初期能力は `data/characters.json`。装備の未確定能力は加算しない。

## 成長配分と経験値

`defaultPolicy` は均等の `balanced`。`pointsPerLevel` は3。`policies` は `balanced`・`attack`・`defense`・`hp` の4種で、各 `attack`・`defense`・`hp` は非負整数、合計3。名前は表示専用で計算はIDを使う。現行配分はユーザー指定の1/1/1・2/0/1・0/2/1・0/1/2。

参加者1人の経験値は `Math.floor(実際に増えた攻略進度 / 出発時の参加人数)`。実進度は必要攻略値で上限となった後の差分。120を3人なら40、7を3人なら2。小数と分配余りは捨てる。人数は帰還時に生存・待機している人数ではなく、保存された `trip.members.length`。全参加者へ同額を付与するので、死亡予定者も分母と付与対象に含める。無進度なら経験値なし。複数パーティが同じ場所から帰還する場合は、保存された遠征順に残り攻略値を加算し、それぞれの実増加量から計算する。

`experience.baseRequired` と `experience.perLevel` は調整用仮値。現在は各45。必要量＝baseRequired＋（現在Lv−1）×perLevel。baseRequiredは正整数、perLevelは非負整数。上昇後は必要量を消費し、余りを次のLvへ持ち越す。成長配分だけは確定仕様、必要経験値の数値は仮設定。

## 保存・表示・戦闘への反映

人物ごとの保存状態は既存の `economyState.companions` に統合する。

- `level`：現在Lv。未保存なら人物のinitialLevel。
- `growthPolicy`：選択方針のID。未保存ならdefaultPolicy。
- `experience`：次のLvへ持ち越す整数経験値。未保存なら0。
- `growth: {attack, defense, hp}`：実際に付与済みの成長累計。現在方針から再生成しない。

方針変更はgrowthPolicyだけを更新。成長時にその時点の方針を使い、累計へ加算する。遠征中でも方針変更可能。帰還報告に経験値とレベルアップを表示する。経験値・進度は帰還時に1度だけ付与し、遠征を帰還待ちから取り除く。

`AdventurerCore.stats` が初期能力と成長累計を合算。装備画面・育成画面・人物詳細・攻略力・怪我判定は同じ能力を参照。治療費は既存のcompanionLevelを使う。出発時に保存済みの攻略力と怪我結果は、帰還時の成長で書き換えない。

旧データの既存Lv・怪我・死亡は維持する。初期Lvや昔の高Lvから過去の成長を推測しない。旧セーブの目的地付き遠征は更新後の帰還で実際に加算した進度分のみ経験値を付与し、目的地なしの旧遠征は従来どおり耐久消耗だけで帰還する。保存versionは2のまま追加項目として扱う。未知の方針、負数・小数経験値、不正な成長値は読み込み時に拒否する。

## 検証と調整

`node --test tests/game.test.mjs` で4配分・方針変更・分配切り捨て・複数レベル上昇・保存・旧セーブ・治療費と攻略力への反映を確認する。`node tools/simulate-expeditions.mjs` は各方針1万回の遠征計算を再現する。現設定の中央値は均等29・攻撃28・防御31・HP31日。経済・章移動・資金条件は含まない。

画面は装備から切り替える独立した育成パネル。方針ボタンは2×2、最小高さ72px。スマホ360×640と390×844で確認し、PCテストはユーザー指示で省略。実機タッチは未確認。
