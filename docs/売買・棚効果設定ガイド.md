# 売買・棚効果

現行mainの設定は `data/trading.json`、純粋計算は `js/trading-core.js`、ゲーム接続・保存検証・表示は `js/trading.js`。セットの正本は図鑑と共通の `data/encyclopedia.json`。正式価格は未設定のままです。

## 設定

- `effects.set.bonus`：セットの購入率加算（0.3 = 30パーセントポイント）。`identical` は同一商品、`slot` は同一装備部位。後二者は `minimum` で必要個数を指定します。効果は重複しません。
- `customers`：安定した `id`、表示名 `name`、既定購入率 `probability`、商品ID別 `items`、カテゴリ（カタログのtypeId）別 `categories`。商品指定→カテゴリ指定→既定値の順。0も有効です。
- `chapters`：既存経済と同じ章ID。`visitors.min/max` は当日の来店者数（両端を含む一様抽選）。`customers` 内で顧客IDごとに所持金 `money.min/max` と基本出現重み `weight` を指定します。現在の全章の数値は動作確認用の共通仮値です。
- `rumors`：ID・名前・継続日数 `duration`・顧客IDごとの重み倍率 `weights`。未指定は1、0は出現停止。複数の噂は倍率を掛け合わせ、合計重みで正規化します。全顧客の重みが0なら来店しません。
- セットの `itemIds` は必要な商品IDの配列。同じIDを2回書けば2個必要です。名称・配置順序には依存しません。定義追加で図鑑も増えます。

## 処理

「翌日へ」で当日の来店・購入を確定します。画面の再描画・再読込では抽選しません。朝の報告に来店・購入人数、ページ式の販売明細を表示します。売上、個体UIDごとの在庫、商品図鑑の販売個数を同時更新します。単品は1品、セットは必要な全個体をまとめて販売し、売れ残りは持ち越します。

各個体の `shelfId` は0始まり。陳列画面で棚を選択して補充・返却します。棚ごとに容量を制限し、セット・同一商品・同一部位の判定で他の棚を合算しません。セットを構成する個体を確保してから余剰を単品候補にします。余剰には同一商品／同一部位／通常のいずれかを適用します。その判定の個数には同じ棚のセット確保済み在庫も含みます。

価格は噂・顧客・棚効果で変動させません。既存の個体耐久による販売額計算は維持します（正式新品価格がnullの場合は開発用200G）。セット価格は各個体の販売額の合計で、割引なしです。商人引取は従来の計算を維持します。

## 未確定事項の暫定ルール

- `rules.setPriority: definitionOrder`：競合するセットは定義順で先に確保。個体は棚内の在庫順で使用。
- セットとして確保中の構成品は単品販売不可。必要個数に入らない余剰だけ単品販売可。
- `rules.minProbability/maxProbability`：初期値0〜1（0〜100%）。
- `rules.selection: uniform`：所持金以内の購入候補から1候補を一様抽選し、その後購入率判定。失敗しても別商品を試しません。同じ商品の単品在庫は個体ごと、セットは組ごとに1候補です。
- セット購入率の基礎値は構成品の購入傾向の算術平均（必要個数分を含む）にセットボーナスを加算。
- `rules.allowUsedInSets: true`：使用済みも許可。falseなら現在耐久＝最大耐久の個体のみセット対象。鍛冶済みは従来どおり陳列・販売不可。

割合、個数、購入傾向、所持金、来店者数、重み、噂の倍率・期間はJSONで変更できます。競合優先方式・抽選方式は現在上記のみを実装し、不明な方式は設定エラーにします。

## 噂・保存・未接続

噂発生元のイベントは未接続です。イベント側から `activateRumor(id)` を呼びます。当日を1日目として指定日数有効。同じ噂の再発動は期間更新。ゲーム日数基準で保存し、読み込みや画面移動では短縮しません。通常画面には有効な噂と残日数を表示します。

自動保存・JSON入出力に噂と前日の販売明細を追加。旧保存にない状態は空で初期化します。棚IDのない旧在庫は従来の配列順に棚容量ずつ割り当てます。図鑑の発見記録は既存の保存方式を維持し、棚変更や販売で消しません。
