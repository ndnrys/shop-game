# 章移動・ストーリー設定

今回の港町→街道の街→王都への出発案内を正式仕様とする。旧ストーリーの章名・敵将・進行は使用しない。第二章の経営は接続しない。

## 定義と責務

- `data/story.json`：イベントID、章、条件、順序、話者とページ、会話抽選の仮重み、日常台詞と段階別の噂。
- `js/story.js`：発生キュー、既読、ページ、加入の一度だけの適用、同行者2人、王都出発、旧セーブ移行案内、保存検証。
- `data/game-settings.json` の `dungeons`：地点ID、章、前提地点、攻略必要値、凶悪度等。
- `chapterProgression.prologue`：港のクリア地点、次章、護衛人数。現行の護衛人数は1人。
- `js/main.js`：既存の朝の収支→声→帰還→重要報告→準備の表示。重要報告が残る間は準備・派遣を開始できない。

## 条件

| 設定 | 用途 |
| --- | --- |
| `condition.day` | 最小日数 |
| `condition.progress: [id, percent]` | 地点の攻略率以上。等号一致ではない |
| `condition.after` / `allAfter` | 前提イベントの発生が必要。表示はキュー順 |
| `condition.merchantVisited` | 営業中の商人来店が必要 |
| `destinationReports` | 派遣に必要な説明報告の既読ID |
| `effect: recruit` | 到着報告の完読時に第一章の3人を加入 |

森80%と100%を一度に超えても、不審船→森の安全→港の事件を全て積む。港解放は港の事件の完読後。地点の前提100%と説明の既読の両方を要求する。初日は派遣不可。毎回翌朝帰還する。

## 今回の仮設定

ユーザーの実装指示を受け、設計書の推奨条件を接続した。緑の目は港50%、北方報告は峠道1%以上、加入は到着報告完了時。丘は交易路、石切り場は峠道の報告完了で解放。会話抽選の通常4・日常2・ストーリー1は調整用の重みで、正式割合ではない。ストーリー候補がない場合は他の候補から抽選する。商人は交易路報告後の営業に必ず登場し、物語は来店後の翌朝に進む。

| 新ID | 必要攻略値 | 凶悪度 | 仮流用元 |
| --- | ---: | ---: | --- |
| harbor_forest | 200 | 3 | 旧森 |
| harbor | 300 | 5 | 旧野営地 |
| trade_route | 180 | 5 | 旧街道 |

| old_checkpoint | 300 | 6 | 旧封鎖陣 |
| herb_hill | 180 | 5 | 旧街道 |

全て`balanceStatus: development-template`。新しい正式価格・能力・報酬は設定していない。背景画像も仮流用で、最終的な港等の絵ではない。

港→街道は既存の借入加算込み必要資金を保持し、移動で消費しない。朝・港クリア報告既読・未払いなし・未整理入荷なし・全遠征帰還・その章の仲間全員生存・護衛1人を条件とする。王都出発にも、既存の章別目標金額を現在所持金で満たす条件と、使用可能な4人全員の生存を要求する。療養中でも同行でき、復帰日までは派遣できない。死亡者は同行候補にしない。蘇生は教会・物資画面からLv×200Gで実行する。同行しない仲間も、その章の使用可能メンバーなら生存必須。

出店資金の25/50/75/100%等の会話閾値は追加しない。港撃退後に資金不足なら朝の案内に必要資金と現在額を表示する。

## 保存・移行

`storyState`にversion・occurred・read・queue・page・escort・merchantVisited・capitalParty・departed・migrationPendingを保存。構造化帰還結果は`groupedReturnReport`で保存する。描画時に加入・出発の効果を再適用しない。王都出発後もchapterは1のままにし、第二章の経営を始めない。4人全員と港に残った人物の装備・育成・療養を保持し、同行する2人を別に確定する。

旧ID forest/camp/eldia_road/velk_blockadeは`legacy: true`として互換用途だけで残す。旧セーブでは移行を明示し、JSONを書き出せる。ユーザーが切替を選ぶまで新ストーリーは始めない。旧実績は旧IDのまま保存し、新しい地点を攻略済み扱いしない。派遣中の旧遠征は既存の翌朝帰還・成長・耐久・負傷計算を維持し、旧地点だけに進捗を加算する。営業途中の移行はその日の営業を終えてから新しい朝の物語に入る。資産の初期化や章戻しはしない。

## 全員生存・現在資金の再判定

`chapterClearConditions()`でメイン攻略・現在所持金・使用可能メンバー全員の生存を共通判定する。過去の目標金額達成を保存フラグにせず、蘇生等で資金が減れば移動不可に戻る。再貯蓄すると移動可能になる。`chapter_one_clear`は互換のため維持するイベントIDで、メイン派遣先の安全確保報告を示す。これの既読だけで章クリアとはしない。

蘇生単価は`data/economy.json`の`revival.costPerLevel: 200`。死亡者本人の現在Lvを掛け、支払った後にdeadとrecoveryDayを解除する。装備・育成は変更しない。現在章の人物のみ蘇生でき、遠征中と所持金不足では実行しない。治療費は30G＋現在Lv×10G＋残り療養日数×30Gに更新した。

章クリア条件・蘇生の追加検証：360×640・390×844で各109項目通過。教会/物資画面の蘇生、費用の帳簿記録、資金不足による移動拒否と再貯蓄後の許可、全員生存、保存復元、3人分の蘇生表示を確認。Node.jsがなくNodeテストは未実行、実機タッチは未確認。

治療料金の設定：`data/economy.json`の`healing.baseCost=30`、`costPerLevel=10`、`costPerRemainingDay=30`。教会・物資画面の表示と支払額は同じ関数で計算する。翌朝に療養が1日進めば30G安くなる。蘇生は引き続きLv×200G。
